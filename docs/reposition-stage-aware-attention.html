方案 2 把每个 stage 的 K/V 视图显式展开；方案 3 让算子按元数据即时生成逻辑视图。两条路径改变的是 Transformer 每层的 Attention，而不是绕过层间依赖。

SECTION 01

同一个目标，两种物理实现

二者共享同一份 stage plan：每个 query 属于哪个 stage、它能看见哪些 token、这些 token 在该 stage 使用什么 RoPE position。差别仅在于逻辑 K/V 视图何时、在哪里被展开。

Scheme 2 · explicit materialization

算子外显式展开

先物化每个 stage 需要的旋转后 K 和 V occurrence，再交给 ragged/varlen Attention。

  3. 03Attention 后丢弃 occurrence buffer，只把最终位置的 active KV 写入 cache。
Scheme 3 · fused logical views

算子内逻辑展开

不创建 K/V occurrence 张量；Kernel 根据 stage 元数据 gather base K/V，并在寄存器中完成 RoPE。

  2. 02逻辑 Ks,r 在 tile 内由 token id 与 position 二元索引定义。
  3. 03通过 online softmax 跨 K tile 合并，不需要物化完整 score matrix。
“一次 Forward”的准确含义

不是在进入模型前提前算完 Attention 数值。第 ℓ 层的 Q/K/V 依赖第 ℓ−1 层的输出，因此仍必须逐层执行；可合并的是原来跨 scheduler turn 的多个 stage，使每一层在同一次外层 model.forward() 内完成 stage-aware Attention。

SECTION 02

SECTION 04

为什么数学上等价？

两种方案只改变张量的物化位置，不改变 Attention 定义。只要 stage membership、token gather、RoPE position 和 mask 完全相同，就能逐层归纳得到相同输出。

STEP 1
qᵢ=WQ·Norm(hᵢℓ−1), kⱼ=WK·Norm(hⱼℓ−1), vⱼ=WV·Norm(hⱼℓ−1)

同一层、同一输入 hidden state，所以 base Q/K/V 相同。

STEP 2
q̂ᵢ=R(pₛ(i))qᵢ，k̂ₛⱼ=R(pₛ(j))kⱼ

方案 2 写进 occurrence buffer；方案 3 在寄存器求值。

STEP 3
aᵢⱼ=q̂ᵢᵀk̂ₛⱼ/√d + Mₛ(i,j)

M 同时编码 stage 可见性、Drop、causal 与可选 sliding window。

STEP 4
oᵢ=Σⱼ∈Jₛ softmaxⱼ(aᵢⱼ)·vⱼ

相同 scores、归一化域和 V，得到相同 O。

STEP 5
Hℓ(2)=Hℓ(3) ⇒ Hℓ+1(2)=Hℓ+1(3)

逐层归纳至 LM Head，因此 next-token logits 相同。

数值实现注意

Kernel 的 tile 顺序、归约树和 online softmax 合并次序可能造成正常的浮点舍入差异，因此工程验证应使用 dtype 对应的 atol/rtol，而不是要求 bitwise equality。对于 scaled RoPE/YaRN，应调用与现有模型完全相同的 R(p)，不能只凭标准 RoPE 的相对位置恒等式替代。

SECTION 06

后端修改范围不同在哪里？

下面是实现提案的预期触达面，不表示当前仓库已经具备方案 2 或方案 3。正式编码仍需独立设计、Plan ID、测试和性能验证。

方案 2：复用现有 Attention 主体

新增 stage plan 和 occurrence materializer；保持模型层循环、输出投影、MLP 和大部分 varlen Attention 语义不变。

PLAN
tokenizer/reposition_sequence.py由逐 turn 派发扩展为可传输的完整 stage execution plan。
↓
WIRE
message.py · core.py携带 query stage、key token id、stage position、cu_q/cu_k。
↓
BATCH
scheduler/scheduler.py · attention/base.py编译批级 stage metadata，并保持 query 顺序。
↓
ATTN
layers/attention.py · attention/fa.py产生 Q_rot/K_occ/V_occ，调用 ragged/varlen Attention。
↓
CACHE
kvcache/mha_pool.py只提交最终 active token 的最终-position KV。

方案 3：Attention 与 RoPE 深度融合

共享方案 2 的 stage plan 和 wire metadata，但不需要 occurrence materializer；改为新增 fused stage-aware kernel 与专用 cache epilogue。

PLAN
tokenizer/reposition_sequence.py · message.py · core.py与方案 2 相同：建立完整 stage DAG 与批级元数据。
↓
API
layers/attention.py · attention/base.py允许 backend 接收未旋转 Q/K base 与 stage position map。
↓
NEW
kernel/triton/stage_aware_attention.pytile 内 gather、RoPE、Drop/causal mask、online softmax。
↓
BACK
attention/fa.py 或新 backend调度 fused kernel，并为 GQA/sliding/sinks 提供显式分支。
↓
EPIL
kvcache/mha_pool.py · cache write kernel按 final_token_ids/final_positions 旋转并提交最终 KV。
共同保持不变

Embedding、Transformer layer 的顺序、output projection、残差、MLP、最终 norm 与 LM Head 的数学定义不变。改变集中在 stage metadata 的生成/传输，以及每层从 QKV 投影之后到 Attention O 之前的路径。

SECTION 07

当前实现与提案边界

当前 mini-sglang Reposition 是 stage-outer 的多 scheduler turn 实现；本页的方案 2、方案 3 是将这些 stage 合入一次外层 Forward 的设计推导，不是已实现能力。

  • python/minisgl/tokenizer/reposition_sequence.py:181-288 · RepositionSequenceState.build_next_msg：在下一有效 Reposition 前截断，并为本 turn 组装 active token、position 与 Drop metadata。
  • python/minisgl/tokenizer/reposition_sequence.py:317-374 · RepositionSequenceState.accept_ack：收到前一 turn acknowledgement 后应用 Drop/Reposition transition。
  • python/minisgl/tokenizer/server.py:178-224 · tokenizer_server：acknowledgement 驱动下一阶段消息派发。
  • python/minisgl/scheduler/scheduler.py:576-618 · Scheduler._prepare_batch / _make_positions：当前 batch 只生成一条扁平 position 向量。
  • python/minisgl/layers/attention.py:51-72 · AttentionLayer.forward：当前使用同一 batch.positions 对 Q/K 做一次 RoPE。
  • python/minisgl/attention/base.py:20-47,362-433 · ContextAttentionBatch / build_context_attention_batch：已有的 ragged Context segment 和 cu_seqlens_q/cu_seqlens_k 基础设施。
  • python/minisgl/attention/fa.py:107-156 · FlashAttentionBackend.forward：当前先把 K/V 存入 cache，再选择普通或 segmented Attention。
  • python/minisgl/engine/engine.py:221-236 · Engine.forward_batch：每个已调度 batch 调用一次模型 forward 并采样 next token。
  • python/minisgl/kvcache/mha_pool.py:16-56 · MHAKVCache：物理 KV buffer 与按 layer 写入接口。
  • python/minisgl/layers/embedding.py:87-100 · ParallelLMHead.forward：Prefill 时选择每个请求的最后 query，再产生 logits。
